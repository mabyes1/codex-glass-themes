# v2.0.1 — 修正背景助手重複啟動 / Prevent runaway background helpers

大型聊天紀錄可能讓助手在登記 PID 前花太久讀取歷史，外層監看程式因而反覆開出新助手；每份助手又可能開出自己的原生背景監看程序，造成記憶體壓力。

## 下載與更新

- **全新安裝：** [Windows x64 EXE](https://github.com/mabyes1/codex-glass-themes/releases/download/v2.0.1/ChatGPT-Glass-Themes-Setup-2.0.1-win-x64.exe)。內附 Node.js，適用 Windows 10 22H2 / Windows 11，組建 19045 以上。
- **已安裝 v2.0.0：** [助手修復 ZIP](https://github.com/mabyes1/codex-glass-themes/releases/download/v2.0.1/glass-theme-helper-repair-2.0.1.zip)。先解壓縮，再用原本安裝佈景的 Windows 帳戶執行 `Repair.cmd`。不必先解除安裝，主題偏好與桌布會保留。

預設安裝位置是 `%USERPROFILE%\CodexGlass`。自訂位置可在解壓縮後的資料夾執行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Repair-ThemeHelpers.ps1 -InstallRoot '你的安裝資料夾'
```

加上 `-CheckOnly` 可先查看安裝目標與程序清單。修復會確認產品、帳戶和完整路徑，備份修改的程式檔，只停止該安裝的助手，再恢復原本的排程啟動設定。原本停用的排程維持停用。

## 修正內容

- 在讀取 session、載入視覺素材、啟動原生背景監看之前，先取得 OS 單一實例鎖並登記 PID。重複助手直接退出。
- 外層監看記住剛啟動的程序；監看程式重啟時，也能以完整腳本路徑找到 PID 尚未登記的助手。
- 每個 session 保存讀取位置、累計 token 與模型名稱。重啟沿用進度，只讀新增內容，檢查點不含聊天文字。
- 沒有有效進度的舊紀錄只讀最後 **256 KiB**，所有 session 每輪合計最多讀 **2 MiB**。超大單行工具輸出有記憶體上限。
- 啟動前及助手離線期間的用量只建立基準，不補播飼料。尾端若缺少 token 基準，下一筆只建立基準；若缺少模型資訊，先歸到其他模型。
- 建置與安裝採檔案存在、大小及執行環境版本檢查。

## 驗證

- 43 項 Node 測試通過，包含 20 份程序同時競爭單一實例鎖、程序崩潰後接手、session 進度續讀及多 session 讀取上限。
- 2.1 GiB 紀錄測試：首次只讀 256 KiB；保存進度後重啟，紀錄沒有新增時，歷史內容讀取量為 0 bytes。
- Windows 隔離修復測試：清除三份重複助手、保留無關 Node 程序，並確認備份與檔案更新。
- EXE 通過實際解壓、隔離部署及內附 Node 語法檢查。

在原本受影響的電腦套用後，正常啟動 Codex 並觀察至少兩分鐘，確認 `theme-host.mjs` 維持一份，原生背景模式的 `NativeBackdropWatch.exe` 維持一份，再確認新增 token 能繼續餵食。

## English

Large session histories could delay PID registration and cause the watcher to launch repeated helpers. This patch claims an OS single-instance lock and publishes the PID before initialization, tracks helpers still starting, and persists per-session token-reading checkpoints. Uncached history reads only its last 256 KiB; all sessions share a 2 MiB read budget per poll.

New users can install the EXE. Existing v2.0.0 users can extract the repair ZIP and run `Repair.cmd` with the same Windows account, preserving Codex, preferences, and wallpaper. Use `-InstallRoot` for a custom path or `-CheckOnly` to preview the repair. The repair validates ownership, backs up changed files, stops only that installation's helpers, and restores its scheduled startup setting.

Local verification passed 43 Node tests, real concurrent-process and crash-recovery checks, a 2.1 GiB session fixture, isolated Windows repair checks, and EXE extraction/staging checks. A normal startup with a large session on an affected second computer remains the final acceptance step.
