# Token 飼料

手動試吃：打開「佈景 → 水族館 → 手動試吃」，點 Astra / Sol / Terra / Luna，一次撒六顆，不會增加真實 token 用量。成功投餵後面板會收起，方便看魚魚；暫停或系統減少動態時會提示先恢復游動。

飼料是小六角 token chips，帶有亮邊和 `‹›` 刻痕，會翻轉慢慢沉降；口味用顏色與光澤區分。

水族館會把本機 Codex 新增的 token 用量換成落下的飼料，魚會追上去吃。
打開「佈景 → 水族館」可以看到助手啟動後的累積用量與各模型用量。

| 模型家族 | 飼料 | 吃完的反應 |
| --- | --- | --- |
| astra | 金色、發光 | 🥹💖✨、金色光暈、輕輕上浮 |
| sol | 淡藍色高級飼料 | 😋💕 |
| terra | 普通棕色飼料 | 😑💭、抖動 |
| luna | 棕色 token chips | 🤢🤮、變綠、吐出綠色碎屑，幾秒後恢復 |
| 其他模型 | 灰色 | 🤔❔，不猜成任何一個家族 |

## 計數規則

- 讀取 `$CODEX_HOME/sessions`，沒有設定時使用 `~/.codex/sessions`。
- 讀 `turn_context.model` 分辨模型，用 `event_msg/token_count` 的 `total_token_usage.total_tokens` 差值累積。重複的相同累積數字不會重複算。
- 使用 Codex 的原始 total tokens；cached input 已在 input 裡，reasoning 已在 output 裡，不再另外加。
- 助手啟動時建立歷史基準，從新用量開始累積；重新啟動助手會重新計數。這是動畫用量計數，不是帳務、費用或剩餘額度。
- v2.0.1 起，每個 session 的讀取位置、累計 token 與模型名稱會保存到 `theme/.runtime/token-cursors.json`。重新啟動會沿用位置，只讀新增內容；助手離線期間的用量建立基準，不補播飼料。檢查點不含聊天文字。
- 沒有有效進度的舊 session 只讀最後 256 KiB，整輪所有 session 合計最多讀 2 MiB，剩下的留給後續輪次。超大的單行工具輸出會略過，避免長字串占滿記憶體。
- 若尾端沒有 token 累計事件，下一筆用量只用來建立基準；若沒有模型資訊，先歸到其他模型，等新的 `turn_context` 再恢復分類。這個取捨避免重播舊用量或為找一筆資訊掃完整份紀錄。
- 追蹤這台電腦上有寫入 session 紀錄的對話。其他電腦與沒有本機紀錄的雲端對話不在範圍內。
- 每兩秒檢查已知檔案與最近日期的新檔，每十五秒重新尋找其他日期的活躍對話。Codex 必須先寫出用量事件，才會掉飼料。
- 各模型分開累積，每 10,000 tokens 一顆。一次大量用量最多以十二顆表現，同時最多四十八顆；面板仍保留完整 token 數。
- 切換其他佈景、暫停、視窗隱藏或系統減少動態時仍計數，新產生的整顆飼料不排隊補播，避免返回畫面突然暴雨。
- 本機檔案唯讀，只有用量數字與模型家族傳到 renderer，不傳送對話內容。

## 驗證

`npm test` 包含累積差值、模型切換、重複事件、歷史基準、分段寫入、零頭累積、動畫數量限制，以及四種口味追食與反應測試。
真實 Codex renderer 已驗證 Sol 真實用量自動餵食；四種口味也在獨立的暫時測試魚缸驗證，各六顆都被吃掉，測試後會移除。

## 攝食動作參考

參考 Higham 的 [Feeding, fins and braking maneuvers](https://pubmed.ncbi.nlm.nih.gov/17170154/)：將口部靠近食物、短距離攝食，再減速。動畫把這個節奏做成接近、制動、吸入、滑行離開與回到原水深；轉向角速度與加速度有上限，只有嘴邊近距離才算吃到。魚種動作是參考後的動畫詮釋；鯨鯊、魟魚、雙髻鯊和海鰻保留巡游，小魚負責搶顆粒。

## 小型搶食戰

每顆 token 可以吸引附近最多三隻魚，注意到的時間略微錯開；每隻魚同時只追一顆。靠近後，第一隻把嘴對準、開始短距離吸入的魚鎖定該顆，沒有預定誰一定獲勝。吃掉時只結算一次。

其他追逐者會往原本位置滑行約 0.25 秒，愣住減速，再冒出 🥺💨 沿弧線回原水深。追超過約 11 秒仍沒抓到，也會放棄休息。銀龍保留較慢的轉向與加速度，因此偶爾撲空或被小魚搶先；上仰保持魚身原始比例。
